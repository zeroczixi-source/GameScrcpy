# 辅助压枪（拖拽视角）/ Recoil Assist

> **引擎原生实现，不需要脚本。** 按住「压枪」节点的热键时，引擎先在该节点位置按住开火按钮，再用一个**独立触点**按标定速度持续向下拖拽视角，抵消散射时的枪口上抬；松开热键立即抬起这两个触点。
>
> 与具体游戏无关：所有参数都在键位侧栏可视化调节，写入 `config/userdata.ini` 的 `user/recoil*`。

## 1. 原理与触发时序

手机上「压枪」等价于：保持开火的同时，手指在屏幕上**持续向下滑动**，把视角往下带，抵消枪口上抬。真实玩家是第二根手指在做这件事，本功能用**第二个模拟触点**复现同样的动作。

```
按下热键
  │
  ├─ 触点 A（开火按钮）  FTA_DOWN @ 节点位置          ← 一直按住，不移动
  ├─ 触点 B（压枪拖拽）  FTA_DOWN @ (dragX%, dragY%)  ← 起点，与开火按钮分离
  │
  ├─ ~100Hz 周期注入（主线程定时器，按真实 dt 积分）
  │     FTA_MOVE @ (x, y + step)   step 由 速率 × 强度 × 力度包络 × 抖动 决定
  │     …（累计位移达到 maxDistance，或触点拖出屏幕 → 停手并抬起触点 B，保持开火）
  │
松开热键
  ├─ 触点 B  FTA_UP @ 最后位置
  └─ 触点 A  FTA_UP
```

要点：

- **两个触点是分开的**：开火按钮保持按住，压枪拖拽是另一个手指，所以压枪期间你仍可以正常用鼠标拉枪、开镜、走位。
- **主线程注入**：注入由 `NativeTimer` 在主线程驱动（`RecoilAssistHandler`，优先级 65），不经过脚本沙箱，也没有跨线程共享状态。
- **步长按真实时间积分**：单步时长上限 100ms，避免掉帧后一次性瞬移。

## 2. 挂载步骤

1. 进入**键位编辑模式**（连接设备后打开键位编辑）。
2. 在左侧「组件」列表里把 **压枪** 拖到游戏**开火按钮**的位置上（不要盖住摇杆/开镜键）。
3. **双击**该节点进入按键录入，然后按下你要用来开火的那个键 —— 鼠标键、键盘键、滚轮都可以，回车结束。绑定成功后节点上会显示键名。
4. 在左侧「参数」分组里展开 **辅助压枪**，按第 4 节调参。
5. 保存键位配置。

> 节点上有一个向下的箭头图标，用来和普通按键区分。它没有齿轮按钮，压枪没有节点级参数，全部是全局参数。

## 3. 快速开始

最小可用配置（默认值即可）：把节点的热键绑成你平时开火用的键（例如鼠标左键），其余保持默认，然后在训练场里长按开火观察。

**第一步永远是先排除「双触点是否被游戏接受」**（见第 6 节排查表最后一条）：把 **启用压枪** 关掉，此时按热键只会按住开火按钮、不注入拖拽。如果这样视角就不跳了，说明跳转来自压枪触点本身。

## 4. 参数表

全部在「参数 → 辅助压枪」分组内，修改即时生效（下一轮注入就按新值算），并持久化到 `config/userdata.ini`。

### 4.1 总开关

| 参数 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| 启用压枪 | 开 / 关 | 开 | 关闭后「压枪」节点退化为「按住开火按钮」，是排查对照实验的关键开关 |

### 4.2 速率

| 参数 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| 垂直压枪速率 | -300 ~ 300 | 6 | 单位 **0.01 屏高/秒**。正数 = 视角向下拖（压枪），负数 = 向上拖（供视角反向的游戏）。`6` 表示 0.06 屏高/秒 |
| 水平压枪速率 | -100 ~ 100 | 0 | 同上单位。正 = 向右，负 = 向左。用于后坐力有稳定水平分量的枪 |
| 压枪强度 | 0 ~ 300 | 100 | 垂直/水平速率的**整体倍率**，100 = 按上面的速率执行，0 = 不压枪（等价于关闭），200 = 双倍 |

### 4.3 起点

| 参数 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| 拖拽起点 X | 0 ~ 100 | 50 | 压枪触点落下位置的横向百分比（屏宽） |
| 拖拽起点 Y | 0 ~ 100 | 50 | 纵向百分比（屏高）。**不要放在开火按钮上**，也不要靠近屏幕边缘 |

### 4.4 步进与拟人化

| 参数 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| 步进间隔 | 2 ~ 50 ms | 8 | 注入频率，8ms ≈ 125Hz。越小越平滑，但会显著增加发包量；卡顿时调大 |
| 间隔随机化 | 0 ~ 100 % | 15 | 每次按下时把间隔随机抖动 ±（该值的一半），避免完全等周期的机械节奏 |
| 步长抖动 | 0 ~ 100 % | 30 | 每一步位移的**乘性**随机抖动。0 = 完全等速 |
| 拟人曲线强度 | 0 ~ 100 | 20 | 按正弦在水平方向来回微摆（周期 0.9s），模拟手指不能完全走直线的特性 |
| 位移上限 | 1 ~ 100 % 屏高 | 35 | 单次按住累计位移上限。手指是**单向累积**的，拖到屏幕边缘就不再产生位移，所以必须有上限 |

### 4.5 力度包络

| 参数 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| 渐入时长 | 0 ~ 3000 ms | 150 | 从按下到达到满力的时间。前几发后坐力小，压枪不宜一上来就满力 |
| 渐入起始比例 | 0 ~ 100 % | 50 | 渐入阶段的起始力度 |
| 渐出时长 | 0 ~ 3000 ms | 0 | 超过该时长仍未松手则开始衰减（0 = 不衰减）。用于连发很久后枪口已经不需要继续压的情况 |
| 渐出结束比例 | 0 ~ 100 % | 0 | 衰减到该比例后保持 |
| 松键宽限 | 0 ~ 500 ms | 60 | 收到「松开」后先按住开火按钮这么多毫秒再真正抬起。**用于吸收按住期间的瞬时松手抖动**（见第 6 节「开火断断续续」）。0 = 关闭（收到松开立刻停） |

## 5. 标定流程

目标：让**压枪拖拽速度 = 游戏真实枪口上抬速度**（1:1 抵消）。

1. **先测后坐力速度 R**：把「启用压枪」关掉。在训练场找一个明确参照物（墙角、靶子边缘），把准星对准它，**长按开火 1 秒整**，然后量准星相对屏幕高度上移了多少（例如屏幕上移了 8% → `R = 0.08`）。
2. **设垂直速率**：把「垂直压枪速率」设为 `R × 100`（上例 → 80）。这个值就是「1 秒压 0.08 屏高」。
3. **试打微调**：装好压枪，长按开火。准星仍然往上飘 → 调大；准星往下沉 → 调小。**建议先只用「压枪强度」做小步微调**（每次 ±10），保持速率值不变，这样换枪时只需要改强度。
4. **调前段/后段**：前 0.2 秒飘得厉害 → 提高「渐入起始比例」；连发后期不需要压了 → 给「渐出时长」一个值。
5. **调水平分量**：如果弹道明显偏右 → 「水平压枪速率」设负值；左右摇摆 → 用「拟人曲线强度」而不是水平速率。
6. **不同枪械**：把每把枪标好的「强度 + 速率」记下来（见下表模板），换枪时改这两个值即可。

| 枪械 | 垂直速率 | 水平速率 | 强度 | 备注 |
| --- | --- | --- | --- | --- |
| 突击步枪（示例） | 80 | -5 | 100 | 前 0.15s 需要更多 |
| 冲锋枪（示例） | 55 | 0 | 100 | 后坐力上升更快、更抖 |
| 轻机枪（示例） | 110 | 0 | 100 | 需要更高的渐出起始 |

> 上表数值只是给一个**量级参考**，必须用第 1 步在你自己设备/灵敏度下实测，不要照抄。

## 6. 排查表

| 现象 | 原因 / 处理 |
| --- | --- |
| 按住热键完全没有反应，连开火都没触发 | 节点热键没绑上（双击节点录入后要回车）；或节点不在开火按钮位置上 |
| 开火了但视角完全不往下走 | 「启用压枪」被关了；「垂直压枪速率」为 0；「压枪强度」为 0 |
| 视角往**上**飘 | 「垂直压枪速率」为正但游戏视角方向相反 → 把它设成负值 |
| **开火时视角突然跳一下，方向随机、偶尔发生** | 压枪触点比鼠标视角触点后落下，部分手游会把「新落下的手指」重新认定为视角手指并重新锚定 → 表现为随机方向跳变。用「启用压枪」关掉做对照：关了不跳 = 就是压枪触点导致，此时只能靠**改变拖拽起点**（避开游戏判定视角用的区域）或调低注入频率缓解。**这必须在目标游戏里实测确认** |
| 压着压着不动了，但开火还在继续 | 到了「位移上限」或触点拖出了屏幕 —— 这是设计行为（保持开火、停止注入）。收紧触发时机或换更小的速率即可 |
| 松手后开火没有停 | 正常不应发生（松手会顺序抬起拖拽触点与开火触点）。若出现，切出窗口再切回会触发失焦兜底释放；把 `output/x64/Release/logs/GameScrcpy_<日期>.log` 里的 `[recoil]` 行发出来定位 |
| 注入一顿一顿的 | 「步进间隔」调大（8 → 15）；或设备本身帧率波动大 |
| **按住开火时射击断断续续（枪声/弹道中途停一下又继续）** | 按住期间引擎收到了瞬时「松开→按下」事件对，开火按钮被反复抬起又按下。先把「松键宽限」保持在 60ms 左右（默认值即可吸收几十毫秒的抖动）；若仍然断续，看日志里有没有 `[MouseDiag]` 行：<br>· 有 `释放事件但 Qt 仍报告该键按下` 或 `重复按下` ⇒ 系统/驱动补发的异常事件；<br>· **两条都没有** ⇒ Qt 送来的是格式正常的按下/释放对，多半是**鼠标微动开关抖动**或驱动补发，换个鼠标/换一个键位（例如改用键盘键开火）即可验证 |
| 换灵敏度 / 换设备后不准了 | 后坐力上抬速度随灵敏度变化，按第 5 节重标 |

日志关键字（`output/x64/Release/logs/GameScrcpy_<日期>.log`）：

- `[recoil] 开始压枪: 开火点=(…)` —— 按下并开始注入
- `[recoil] 停止压枪: 原因=… 时长=…` —— 停止；`原因` 区分 `release`（真人松手且宽限到期）/`release-grace`（宽限到期）/`reset`（失焦、切模式等兜底）
- `[recoil] 吸收一次抖动释放（<Nms），开火触点保持按下` —— 宽限窗口内又收到按下，判定为抖动并忽略
- `[recoil] 压枪总开关已关闭：只按住开火按钮，不注入补偿拖拽` —— 总开关关闭时的对照实验
- `[MouseDiag] …` —— 鼠标事件自洽性诊断（只在事件异常时出现，见上表）

## 7. 已知限制

1. **开环前馈**：按标定速度匀速补偿，不能逐发修正。枪口移动被游戏其他机制（跑动、受击抖动）干扰时无法跟随。
2. **双触点假设**：部分手游只把第一个落下的触点当作视角手指，或对多指拖拽有特殊处理。压枪触点是否被当作视角输入**必须在目标游戏里实测**（第 6 节第三条）；这是「视角突然跳」的首要嫌疑。
3. **单向累积位移**：手指从起点往一个方向越拖越远，拖到屏幕边缘即失效，所以有「位移上限」，单次按住时间过长会停手。
4. **松手即停**：没有「缓收」（抬起后再缓慢回补一小段）。
5. **与鼠标视角叠加**：压枪触点和鼠标拖拽视角是两个独立手指，游戏会把两者的位移叠加 —— 这既是压枪能生效的原因，也意味着压枪期间手动拉枪会被叠加一个向下分量。不想要时用总开关或降低速率。
6. **换灵敏度/设备需重标**：见第 5 节。
